# Auto-Purchase-for-GPT

本地 AdsPower 并发 GPT 升级控制台。

## 任务时间上限

一条任务从开始执行起总共 10 分钟，浏览器启动、登录、选套餐、填卡、支付等待以及所选截图、CPA、2FA 共用同一个截止时间。各小阶段没有独立的提前超时，也不会重新获得 10 分钟；排队时间不计入。达到上限只关闭当前 Profile，其他并发任务继续。付款成功、已完成截图、CPA JSON 和已读取的 2FA Key 保留。

用户通过单项按钮新发起的附加任务也只有一个 10 分钟总预算，内部所有步骤共享。

## CSV 字段

```text
adsPowerSerialNumber,email,cardNumber,expires_at,cvv
```

首列是 AdsPower 的 `serial_number`，页面最多接受 100 条任务；并发数限制为 1-10。并发为 5 时会同时执行列表中的 5 条，完成一条就按原列表顺序立刻补上下一条，始终保持 5 条在跑（剩余不足 5 条时自然减少）。当前只处理个人版 `Pro`，AdsPower 月费规格可选择 `$100`、`$200` 或 `$500`，默认 `$200`。新版 Pro 卡片显示 `Frontier intelligence`；有规格按钮时先选金额并确认月费，再点击同一卡片内唯一的购买按钮；没有规格按钮时先进入结账配置页，在 `Pro plan` 中选择指定金额。两种布局都核对最终 `Due today` 后才填卡。启动后会从 ChatGPT 当前个人套餐页读取并展示实际识别到的套餐，团队版和其他升级产品暂不进入此流程。任务失败后可点击页面主操作区的“重试”重新执行全部失败行，或点击某一行后面的“重试”只重跑该行。每行“重试”后提供“从本行继续”：从本行开始按列表顺序执行后续可执行行，跳过已完成或已付款行，沿用当前并发数、套餐和附加选项，复用原账号、卡和地址；执行中禁用。执行中可点击“停止排队”：正在跑的条目继续跑完，还没开始的排队任务不再执行。每条任务从开始执行起最多 10 分钟，包含登录、填表、按钮启用等待、付款结果等待及附加任务。10 分钟内没有明确失败就继续等待支付页面变化；达到上限只结束当前条并关闭对应浏览器，其他并发任务继续。已确认付款的任务保留成功状态及已有附加结果。

AdsPower CSV 使用上述五列，不需要密码。旧模板仍可导入，但 password 列会被忽略，不进入任务或请求。暂停开发的无痕模式保留原有密码及 mailAccess 格式。页面提供“Billing 地址州”下拉框，默认 `Oregon / 俄勒冈州`。OR 地址池在 `public/app.js` 的 `OR_BILLING_ADDRESSES` 中维护，按用户原表保存 23 条街道、城市、州和邮编组合。导入 CSV 时，每条任务随机抽取一整条地址（允许重复），并在 CVV 后面的“Billing 地址”列展示；姓名沿用现有随机生成方式。任务重试复用首次导入时绑定的地址，不会临时更换。新地址池在刷新控制台后新导入的任务中生效，已导入行不自动替换；地址数据尚未验证实际有效性。

## 启动与分发

不用复制整个项目，按系统发送启动文件即可：

- **Windows**：发送 `start-windows.bat` 和 `start-windows.ps1`，放在同一文件夹，双击 BAT。PowerShell 文件保留 UTF-8 BOM，支持 Windows PowerShell 5.1。
- **Mac**：只发送 `start-mac.command`，双击运行，支持 Apple Silicon 和 Intel。建议发送启动文件 ZIP，解压后运行，以保留可执行权限。
- **本地开发**：在项目目录运行 `./start-local.sh`，复用本机项目和同一套启动流程。

两个系统使用相同流程：检查 Node.js 22+ 和 Git → 没有项目则从 GitHub 的 main 下载 → 已有项目则快进更新 main → 启动本地服务。首次下载到用户目录下的 `Auto-Purchase-forGPT`；启动文件放在本项目目录时优先使用当前项目，所以开发机也使用同一入口。也可用环境变量 `GPT_UPGRADE_PROJECT_DIR` 指定项目目录。

Windows 缺少 Git 或合适的 Node.js 时通过 winget 安装，需完成系统安装提示；系统没有 winget 时先安装 Microsoft 的 App Installer。Mac 缺少 Node.js 时自动从 nodejs.org 下载适配处理器的 Node.js 22 LTS，校验 SHA256 后存入本工具的用户缓存，无需 Homebrew 或管理员权限；缺少 Git 时调起苹果 Command Line Tools 安装，安装完成后继续。依赖安装需要联网，系统安装提示需要用户操作。

本地有未提交修改或不在 main 分支时，保留当前代码并运行，明确提示未更新；分支分歧或网络更新失败同样保留本地版本。不会强制切分支或 `reset --hard`，不会删除日志或本地配置。首次下载失败不留下半成品目录。若端口已占用，会在更新前停止，避免重复双击打断原来正在执行的任务；请使用已打开的服务，或者先结束旧服务再启动更新。

当前 GitHub 仓库匿名访问不可用，新电脑需要有仓库访问权限的 GitHub 账号，并完成 Git 的登录提示。脚本不包含个人 token；已有 Git 凭据会复用，未授权电脑不能仅靠启动文件读取私有代码。

启动后手动访问 `http://127.0.0.1:4173`，不自动打开浏览器。保持启动窗口打开，按 Ctrl+C 停止。新电脑需另行安装并登录 AdsPower，开启 Local API，再在控制台“设置”填写该电脑的地址和 API-Key。

只保留 Windows、Mac 和本地开发三个场景的四个脚本；已删除旧 Windows 名称 `start-local.bat`、`start-local.ps1`。给其他电脑分发时使用上面带系统名称的文件。Mac 文件若被传输工具去掉执行权限，可在终端运行 `chmod +x /实际路径/start-mac.command` 后再双击。

## 充值后附加选项与 CSV 导出

充值前可选择附加任务，“截图”默认勾选；所有附加项都未勾选时，在确认支付成功后直接完成并关闭当前 Profile。“导出 CPA”和“启用并导出 2FA”可选（仅 AdsPower）。按截图 → 下载发票 → CPA → 2FA 的顺序执行所选步骤。等待已勾选附加项的结果后结束，截图异常单独记录，不把已付款任务放入充值重试。拒付或支付尚未确认时不能算成功。

任务列表右上角“导出 CSV”下载当前全部任务：邮箱、密码、订阅类型、cpa、2fa、AdsPower编号、任务状态、失败原因、截图状态、结束时间、2FA状态、CPA状态。cpa 列保存本次 Codex 授权结果的紧凑 JSON 字符串；2fa 列保存本次读取的 Key，是否完成启用以 2FA状态 列为准。订阅类型保留每行启动时选择的规格；待执行行用当前选择，须结合任务状态判断是否已订阅。文件含 UTF-8 BOM，可用 Excel/WPS 打开，文本按原值做 CSV 引号转义。结果导出的密码列保留兼容，AdsPower 新导入任务该列为空。卡号、有效期、CVV 和完整地址不加入导出。

CSV 在浏览器内生成，服务端不保存导出文件或账号密码；刷新页面后需重新导入。执行中锁定导入、规格及附加选项；可随时导出当前状态。已完成账号不会通过单行重试或整批启动再次充值。

AdsPower 状态链：地址填完 → 持续等待结账按钮启用或明确失败 → 点击订阅一次 → 持续等待明确支付成功/拒付 → 按选项截图、导出 CPA、配置 2FA，或直接完成。按钮暂时禁用、转圈或页面没有变化均不算失败；付款等待不设单独的 60/90 秒上限，统一受整行 10 分钟硬上限控制，等待期间不暂停计时。普通状态通知不会当作拒付；提交后不因页面无变化自动补点。等待中的任务继续占用自己的并发位，其他并发任务照常执行；“停止排队”仍只取消排队项。任务入口统一使用整行剩余时间，原有套餐及局部补点动作保留。

## 2FA 自动设置与导出

勾选“启用并导出 2FA”后，程序在确认支付成功后自动执行：Settings → Security and login → Authenticator app → Continue → Key → 读取 Key → Continue → 本机生成并逐字符输入 6 位 Code → Continue → 确认开关已开启。无需手动复制，也无需访问 2fa.co.com。TOTP 使用 SHA-1、30 秒周期、6 位数字；接近周期结束时先等新周期，系统时间须准确。

Key 一读取到就保留，验证失败或任务总超时仍可导出，2FA状态 会明确提示未完成；已有 2FA 的账号不会被关闭或重置，也不会假造其原密钥。截图、CPA 和 2FA 的结果单独显示，一项异常不阻止另一项；已付款任务不进入充值重试。

Key 和验证码不写日志、不广播给其他控制台页面。当前页面使用批次令牌从服务内存读取 Key；导出 CSV 的 `2fa` 列保存 Key，`2FA状态` 列区分已启用、未完成、原已启用但无 Key。服务不落盘保存这些秘密；请在刷新或关闭控制台页面前导出，已经取回页面内存的 Key 在服务关闭后仍能导出。

动作与成功判据：安全页 → 唯一 Authenticator app 开关；开关 → 介绍；Continue → Key；Key → 已选中且唯一 Base32 密钥；Continue → Code 输入框；填入验证码并提交 → 弹窗退出且开关开启。各状态只使用整行剩余时间，不设独立 10 秒阶段上限；整行结束保留已读取 Key 及已有结果。

## 手动终止等待

正在执行的行在“从本行继续”后显示“终止本行”，点击后立即中断该行等待/连接并请求关闭 Profile，释放并发位给后续排队项；其他运行行继续。“停止排队”只取消尚未开始的条目。HTTP `POST /api/jobs/:jobId/rows/:index/stop` 使用当前批次令牌和原 UI 行号，立即返回 202，待关闭处理和终态事件后解锁操作。

未提交支付的行标记“已取消”，可在批次结束后单行重试或从本行继续；已确认付款时保留成功、截图、CPA 和 Key，只标记未完成附加项。已经提交付款但没有结果时终止会标记“待核实”，刷新后仍阻止重复充值，请先核对账单；终止程序不会撤销已经提交的付款。

点击终止本行 → 中断该行 CDP/启动请求 → 关闭处理结束后收到 row_cancelled / row_succeeded / additional_finished，后续排队行接续执行。正常业务继续共用原 10 分钟上限；结束后的 AdsPower 关闭请求最多等 5 秒，防止 API 卡住继续占用并发位。
